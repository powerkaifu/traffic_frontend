## 🎯 演示流程 (5 分鐘版本)

### 時間分配

- 打開系統: 30 秒
- 啟動自動模式: 10 秒
- 展示時段轉換: 2 分鐘
- 驗證後端數據: 1 分鐘
- 解說和問答: 1.5 分鐘

### 詳細步驟

#### 1️⃣ (0:00-0:30) 系統介紹

```
展示內容:
• 點開瀏覽器，導航到 http://localhost:9001
• 展示交通模擬主頁面
• 說明: "這是前端視覺層，顯示 60-80 輛車用於評審演示"
```

#### 2️⃣ (0:30-0:40) 打開控制台

```
操作:
• 按 F12 打開開發工具
• 切換到 Console 標籤
• 說明: "這裡可以看到系統的正規化過程"
```

#### 3️⃣ (0:40-2:40) 啟動自動模式並觀看轉換

```
操作:
• 點擊"自動模式"按鈕
• 讓系統自動運行，涵蓋多個時段轉換點

觀看時間點:
00:00 → 凌晨時段
  └─ [正規化] 時段=late_night, displayMultiplier=1.5x

08:00 → 尖峰時段
  └─ [正規化] 時段=peak_hours, displayMultiplier=7.2x

09:00 → 離峰時段 (自動轉換)
  └─ [正規化] 時段=off_peak, displayMultiplier=3.0x ← 自動轉換！

14:00 → 仍在離峰
  └─ [正規化] 時段=off_peak, displayMultiplier=3.0x

17:00 → 再次尖峰 (自動轉換)
  └─ [正規化] 時段=peak_hours, displayMultiplier=7.2x ← 自動轉換！

說明:
"系統自動檢測時段變化，無需手動干預。
displayMultiplier 值隨時段改變，
用於控制視覺層與後端 API 層的數據比例。"
```

#### 4️⃣ (2:40-3:40) 驗證後端數據

```
操作:
• 打開 Network 標籤
• 尋找 POST 請求到 "predict" 的 API 呼叫
• 檢查 Request Body

展示內容:
"看這個 API 請求:
  • Volume_T: 8.33 (後端接收的正規化值)
  • original_volume: 60 (前端視覺值)
  • displayMultiplier: 7.2 (轉換倍數)

公式: 60 / 7.2 = 8.33 ✓
(視覺值 / 倍數 = 後端真實值)

後端 AI 模型基於 50 週 VD 訓練數據，
期望接收 5-10 輛車的數據。
8.33 輛完全符合期望範圍！"

檢查 Response:
"後端返回的綠燈建議:
  • 東西向: 28 秒
  • 南北向: 32 秒

這些時間會自動更新到燈號顯示。"
```

#### 5️⃣ (3:40-5:00) 總結和問答

```
說明要點:
1. 前端視覺層: 60 輛車 (評審清晰看到流量情況)
2. 自動時段檢測: 無需手動切換 (完全自動化)
3. API 層正規化: 8 輛車 (符合 AI 訓練數據)
4. 雙層架構: 既有視覺效果，又符合模型需求

回答可能的問題:
Q: 為什麼要做正規化?
A: 前端需要 60 輛車才能清晰展示流量情況，
   但 VD 訓練數據範圍是 5-10 輛車。
   正規化層自動轉換，使兩層數據相容。

Q: 時段邊界是怎樣轉換的?
A: 完全自動。系統每次更新時檢查當前時刻，
   自動選擇對應的時段和 displayMultiplier。

Q: 三時段有什麼區別?
A: displayMultiplier 不同:
   • 尖峰 (7.2x): 倍數最大，車流最密集
   • 離峰 (3.0x): 倍數中等，正常交通
   • 凌晨 (1.5x): 倍數最小，車少流暢
```

## ⚠️ 故障排查

### 問題: 看不到 [正規化] 日誌

**解決步驟:**

1. 確認已按 F12 打開控制台
2. 確認已點擊"自動模式"或時段按鈕
3. 檢查是否有紅色錯誤信息
4. 重新整理頁面 (Ctrl+R)
5. 檢查 Quasar 服務器是否仍在運行

### 問題: Network 中看不到 API 請求

**解決步驟:**

1. 確認後端服務器在線 (http://localhost:8000)
2. 在 Network 標籤點擊"自動模式"按鈕
3. 尋找包含 "predict" 字樣的 POST 請求
4. 檢查請求狀態碼 (應為 200)

### 問題: API 返回 4xx 或 5xx 錯誤

**解決步驟:**

1. 檢查後端是否正常運行
2. 檢查 API 端點是否正確 (localhost:8000)
3. 查看後端日誌了解具體錯誤
4. 檢查請求體格式是否正確
