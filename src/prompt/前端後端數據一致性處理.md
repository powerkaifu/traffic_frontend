## 前端與後端數據一致性處理方案

### 1. 問題識別

最初發現前端模擬數據（特別是車輛流量 `Volume`）與後端模型訓練數據的範圍存在不一致。後端模型是基於 `vd_data` 進行訓練的，其原始 `Volume` 值普遍較低（例如，單一車道單一車種的流量通常不超過 20）。然而，前端模擬在未經處理的情況下，可能產生超出此範圍的流量數據。

### 2. 核心理解轉變

在處理過程中，我們釐清了一個關鍵點：後端模型並非每次都重新訓練，而是一個**固定且預先訓練好的模型**，其主要目的是用於模擬前端數據。這意味著前端必須調整其數據，以符合這個固定模型在訓練時所見的數據分佈和範圍。

### 3. 處理目標

確保前端模擬產生的數據，在傳送給後端固定模型之前，能夠符合該模型訓練時所依據的數據範圍和特性，從而提高模型在模擬環境中的預測準確性。

### 4. 實施方案

為達成數據一致性，我們對前端的程式碼進行了以下修改：

#### 4.1. `TrafficLightController.js` 的修改

- **重新引入 `dataScalingFactor`：** 為了將前端模擬產生的原始 `Volume` 數據縮放到後端模型訓練時所見的範圍，我們重新引入了 `this.dataScalingFactor` 並將其設定為 `0.2`。
  - **修改前：** `// this.dataScalingFactor = 0.02 // [修改] 數據縮放因子，使其更接近真實數據 - 已移除，前端直接傳送原始數據給後端處理`
  - **修改後：** `this.dataScalingFactor = 0.2 // 重新引入縮放因子，將前端數據縮放到後端模型訓練範圍`

- **應用縮放因子於 `Volume` 計算：** 將 `collectIntersectionData` 函數中 `Volume_M`、`Volume_S`、`Volume_L` 的計算方式修改為使用這個新的 `dataScalingFactor`。
  - **修改前：**
    ```javascript
    const scaledMotor = data.motor
    const scaledSmall = data.small
    const scaledLarge = data.large
    ```
  - **修改後：**
    ```javascript
    const scaledMotor = Math.round(data.motor * this.dataScalingFactor)
    const scaledSmall = Math.round(data.small * this.dataScalingFactor)
    const scaledLarge = Math.round(data.large * this.dataScalingFactor)
    ```

#### 4.2. `AutoTrafficGenerator.js` 的修改

為了進一步控制前端模擬產生的原始流量，使其更符合後端訓練數據的特性，我們調整了車輛生成器的參數：

- **調整 `defaultConfig.interval` (生成間隔)：** 增加生成車輛的間隔時間，以降低整體流量。
  - **修改前：** `{ min: 6000, max: 15000, normal: 10000 }`
  - **修改後：** `{ min: 15000, max: 30000, normal: 20000 }`

- **調整 `defaultConfig.densityThresholds` (密度閾值)：** 提高閾值，使其更難達到高密度狀態，從而保持較長的生成間隔。
  - **修改前：** `{ light: 5, moderate: 10, heavy: 15, congested: 20 }`
  - **修改後：** `{ light: 10, moderate: 20, heavy: 30, congested: 40 }`

- **降低 `maxLiveVehicles` (最大同時車輛數)：** 限制模擬中同時存在的車輛總數，間接控制每個方向的流量。
  - **修改前：** `200`
  - **修改後：** `50`

- **調整 `trafficProfiles` 中的 `peakMultiplier` (尖峰乘數)：** 普遍降低 `peakMultiplier` 的值，這會增加生成間隔，進一步減少不同時段的車輛生成率。
  - **修改前（部分範例）：** `peakMultiplier: 1.5` (上午尖峰), `peakMultiplier: 1.4` (傍晚尖峰)
  - **修改後（部分範例）：** `peakMultiplier: 0.8` (上午尖峰), `peakMultiplier: 0.7` (傍晚尖峰)

### 5. 預期成果

透過上述修改，前端現在將傳送經過縮放且流量更符合後端固定模型訓練數據範圍的數據。這有助於提高後端模型在模擬環境中預測綠燈秒數的準確性和穩定性。
